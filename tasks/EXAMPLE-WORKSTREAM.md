# BILLING SPIKE

## Goal
Something used far more credit than usual in the last three days. Find out what, and propose a fix.

## Read first
- Memory notes on the app (deploy recipe, where usage is logged).
- The usage logs on the server. Read only.

## Steps
1. Pull usage by user and by day for the last two weeks.
2. Find what changed when the spike started: a deploy, a new user, a new feature.
3. Propose a fix and what users would notice.

## Hard limits
- Read-only on the server. Ask before restarting or deploying anything.
- Messages to users are drafted and shown to me, never sent.

## Done means
- Your closing reply has the cause, the evidence and a proposed fix.
- Add a STATUS row for this workstream and keep it current. Message CONTROL TOWER when done, blocked or needing me.
